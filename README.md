# Avito Candidate Generation

Решение задачи поиска до 50 объявлений для каждого benchmark-запроса. Обучающие данные содержат положительные взаимодействия запросов с объявлениями. Итоговая метрика отправленного решения - **Stepik Recall@50 = 0.678731**.

## Финальный поиск

Пять источников возвращают кандидатов для каждого запроса:

| Источник | Поле объявления | Глубина | Вес RRF |
| --- | --- | ---: | ---: |
| Глобальный word TF-IDF | заголовок и параметры | 500 | 1.00 |
| Глобальный char TF-IDF | заголовок | 500 | 0.75 |
| Глобальный multilingual-e5-small | заголовок | 500 | 1.75 |
| Char TF-IDF в локации запроса | заголовок | 100 | 0.25 |
| Word TF-IDF в локации запроса | заголовок и параметры | 100 | 0.25 |

Выдачи объединяются по `Σ weight / (60 + rank)`. Найденные объявления из локации запроса получают бонус `0.05`; после сортировки остаются top-50. Параметры закреплены в [hybrid_config.json](hybrid_config.json). E5 используется без дообучения, с фиксированной revision.

## Воспроизведение отправленного ответа

Нужны Python 3.12 и три файла данных:

```text
data/train.parquet
data/benchmark_queries.parquet
data/benchmark_items.parquet
```

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python run.py --config hybrid_config.json --output answer.csv
sha256sum answer.csv
```

Контрольная SHA-256 отправленного CSV: `63156370da6d0931449495c5c816661f8148390e4a756ac80663d91947ab03c0`. Повторная генерация с готовыми кешами и флагом `--cache-only` дала побайтово тот же CSV. Данные, веса модели и кеши не включены в Git. При первом запуске скрипт скачает закрепленную версию E5 и построит индексы.

Для сверки исходных данных SHA-256: `train.parquet` — `e150ab7a5c98769f643b95ee3a02dc0f664b647facd69a7d280ec6d48ca554a7`; `benchmark_queries.parquet` — `e49de4fb76f03979a4af96034817767d39ae5de9f94e254fed028243188dda06`; `benchmark_items.parquet` — `193b3a3961464620cbf8d8797152b7f90cae1826ca749fb7817a210984a09899`.

`run.py` генерирует и проверяет CSV; `src/` содержит поиск, объединение выдач и проверку ответа. Ноутбуки показывают подготовку данных и локальную оценку финального метода. Локальный validation разделен по нормализованному тексту запроса. Для финальной конфигурации Recall@50 на quick равен **0.690799**, на confirmation - **0.685595**; candidate recall на confirmation - **0.840209**.
